# Test plan

One suite per notebook, with the same case IDs, in the same order, in both implementations; each case is a markdown
cell `## ID · title` followed by one code cell. `support.py` holds the shared helpers. TypeScript's plan lists only its
differences.

`Dataclass`'s candidates, one per value of `frozen` and `slots`, for each object schema it renders, and none for those it does not (an inline object, another format's native, a list bounded by a term, a named native, a named union, parameters and terms, which are not built yet), types dropped where they are held as `Any` (an inline object or union, another format's native, nested nine deep), `missing` before and after a run, lists of a class nested nine deep rendered, a named native's field naming its alias; questions); incremental rebuilds (mbse-patterns' plan).
